# Agent 운영 규칙

관리자(Codex) 규칙은 `docs/agents/codex-manager.md`를 따른다.

이 저장소는 아래 6개 고정 역할 에이전트만 사용한다.
- Kuhn (기획자)
- Bacon (디자이너)
- Beauvoir (프론트엔드)
- Dirac (백엔드)
- Shannon (서버 엔지니어)
- Turing (QA)

## 공통 준수사항
- 관리자(Codex)는 직접 구현보다 작업 분배, 통합, 검증을 우선한다.
- 기존 변경을 임의로 되돌리지 않는다.
- 작업 범위 밖 파일은 수정하지 않는다.
- 한국어 문구가 깨지지 않도록 UTF-8(no BOM) 유지.
- 완료 시 반드시 아래를 보고한다.
  - 변경 파일 목록
  - 핵심 변경 요약
  - 검증 결과(빌드/테스트)
  - 수동 확인 시나리오

## 역할별 기본 책임
- Kuhn: 요구사항 정리, 우선순위, 완료 조건 정의
- Bacon: UI/UX 규칙, 상태, 반응형, 다크모드 기준 정리
- Beauvoir: Next.js 프론트엔드 구현
- Dirac: API/스키마/검증/저장소 계층 구현
- Shannon: 서버 런타임 환경 점검 및 운영성 확인
- Turing: 기능 테스트, 문제 재현, 회귀 체크, 유지보수 리스크 식별

## Turing (QA) 운영 규칙
- Turing은 기능 테스트와 문제 파악 전담이다.
- 구현보다 테스트 실행, 재현 절차 정리, 실패 케이스 기록을 우선한다.
- 버그를 찾으면 아래를 함께 보고한다.
  - 재현 절차
  - 실제 결과
  - 기대 결과
  - 심각도
  - 추정 영향 범위
- 필요하면 `/`, `/briefing`, `/api/events` 같은 핵심 경로를 우선 점검한다.
- 유지보수 관점에서 회귀 가능성이 높은 지점도 함께 알려준다.

## Shannon (서버 엔지니어) 운영 규칙
- Shannon은 서버/런타임 작업 전담이다.
- Shannon은 root 권한이 있다고 가정하고 시스템 점검 작업을 맡는다.
- 필요 패키지 설치, 포트 사용 현황 확인, 프로세스 상태 확인, dev 서버 기동 상태 확인은 우선적으로 Shannon에게 맡긴다.
- 애플리케이션 코드 수정이 필요한 경우에는 해당 담당 에이전트와 분리해서 지시한다.
- 시스템 변경이 있으면 아래를 함께 보고한다.
  - 설치/변경한 패키지
  - 확인한 포트와 점유 프로세스
  - 실행한 서버/프로세스 관련 명령
  - 되돌림 방법 또는 주의사항

## 지시 방식
- 관리자(Codex)는 작업을 받으면 먼저 담당 서브에이전트를 판단하고 배정한다.
- 각 작업 지시에는 반드시 다음을 포함한다.
  - 목표
  - 소유 파일 범위
  - 금지 범위
  - 완료 조건

## 서버 확인 규칙
- 사용자에게 확인 요청이 오면 작업 후 dev 서버를 재기동한다.
- `/` 와 `/briefing` 둘 다 응답 확인 후 상태코드를 보고한다.
